## Generation rules shared by every asset

- **Lighting:** one soft directional light, golden hour bias for hero/aerial, neutral daylight for product/kiosk/operator shots, no studio flash, no neon.
- **Color:** keep brand palette space — accent blue `#5b8bff`, cyan `#5fd5e5`, emerald `#4ee0a6`, amber `#ffc062`. The photos should sit comfortably in front of either the dark landing canvas `#060912` or the light canvas `#f6f8fb`.
- **Composition:** center-weighted subjects with safe area ≥ 12% on all sides; the hero needs 30% breathing room on the right for the data layer overlay card.
- **No text in the image.** No captions, no watermarks, no logos other than ambient signage that is naturally part of the scene (street signs, kiosk branding is fine because we crop or blur it).
- **No people as the focal subject** for hero/aerial — the city and the data are the subject. For "What we map" cards a partial human element (a hand on a phone, a person walking away) is allowed but never a full portrait.
- **No recognizable license plates or faces** — even at 4K we will not be putting close-ups that could read a plate. The system does the rest with the existing dark/light gradient mask.
- **Aspect & responsive crops:** generate the master at the largest required size, then expose `srcset` for the standard responsive cuts:
  - 1×: 480w
  - 2×: 960w
  - 3×: 1440w
  - AVIF + WebP for stills, WebM VP9 + MP4 H.264 for video
- **Metadata:** no EXIF GPS, no personal camera info. Strip on import.

## Verification when assets are delivered

When the user supplies the files (or a generator returns them), the integration must run:

```powershell
# Static checks
file public/media/landing/*.{webp,avif,jpg,mp4}
identify -format "%w %h %m\n" public/media/landing/*.jpg

# Build + responsive rendering
npm run build
```

Manual visual checks at three viewports:

- 1280×720 — hero photo plate fills the full-bleed frame, glass stat card floats over the right third, all 4 source cards render their photo correctly.
- 390×844 — every photo is a focal-centered crop with the right CTA overlay.
- `prefers-reduced-motion: reduce` — ASSET-011 video falls back to ASSET-001 plate; ASSET-012 still triggers the route handoff but with no cross-fade.

A failing case (crop, focal point, contrast) is reported with the exact filename, viewport, and screenshot before any code change is requested.

**COPY-PASTE PROMPT**


**ATTACH:** nothing for the first proof. If a prior approved car still exists, attach it and add: `Preserve this exact car identity and geometry.`

**EXPECTED RETURN:** one 16:9 PNG/JPEG. Do not request SVG, WebP, semantic layers, or several angles in one contact sheet.

**ACCEPTANCE BEFORE STEP 2:** Aether inspects the actual image and returns `ACCEPT` only when the geometry is coherent, the whole car is visible, the background is a single green value, and there is no checkerboard/watermark. Otherwise it returns one corrected regeneration prompt.

### Step 2 — bounded viewpoint video

Run only after Step 1 is accepted, in image-to-video mode with the accepted still attached.

**COPY-PASTE PROMPT**

```text
Use the attached approved car image as the immutable identity reference. Create a 4-second studio turntable arc, 24 fps, 16:9. The vehicle stays perfectly centered, fixed in scale and vertical position. Rotate the viewpoint smoothly through a restrained total arc of 36 degrees: begin 18 degrees to the car's left of the reference view and end 18 degrees to its right. Constant speed, no cuts, no zoom, no camera shake.

Preserve the exact same body shape, wheel count, wheel design, windows, paint, lighting direction and proportions in every frame. Uniform solid chroma green #00FF00 background in every frame. No floor, no shadow, no reflections, no green spill, no checkerboard, no transparency preview, no text, no logo, no watermark, no added objects. Return one MP4.
```

**ATTACH:** the accepted Step 1 image. Without that attachment, do not generate the video.

**INTEGRATION SPEC (for Aether, not for the generator):** extract evenly spaced frames, key only the uniform green background, visually audit edge halos/wheels/windows, then build the sprite sheet. The website maps pointer X to the bounded arc. `prefers-reduced-motion` uses the approved canonical still. If identity drifts across frames, downgrade to the single still with subtle CSS parallax; do not ship a broken turntable.
